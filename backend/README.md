# 档案台账后端

当前为1.0.0版本。独立Node.js HTTP服务，使用SQLite文件数据库；档案、附件、导入任务、账号权限及日志由后端持久保存。第六阶段增加生产页面托管、备份校验与恢复工具。

## 启动

需要Node.js 24或更高版本。首次使用：

```powershell
cd D:\档案\backend
npm ci
npm start
```

默认监听`http://127.0.0.1:3001`。另一个终端运行前端：

```powershell
cd D:\档案\frontend
npm run dev
```

浏览器打开`http://127.0.0.1:5173/`。前端开发代理把`/api`转发到独立后端。首次打开自行创建管理员账号，没有默认账号密码。业务接口必须登录，写请求还需CSRF令牌。当前按本地开发运行，正式部署属于第六阶段。

## 配置

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| PORT | 3001 | 后端监听端口 |
| ARCHIVE_DB_PATH | backend/data/archive.sqlite | SQLite文件位置，支持绝对路径 |
| ARCHIVE_ALLOWED_ORIGINS | http://127.0.0.1:5173,http://localhost:5173 | 允许的浏览器来源，逗号分隔 |
| ARCHIVE_COOKIE_SECURE | 未设置 | 设为1启用Secure Cookie，仅用于HTTPS环境 |
| ARCHIVE_STATIC_DIR | 未设置 | 生产前端构建目录；开发API模式可省略 |
| ARCHIVE_HOST | 127.0.0.1 | 宿主机本地默认值；Docker内设为0.0.0.0以接收端口映射 |
| ARCHIVE_TRUST_PROXY | 未设置 | 设为1仅信任本机代理传入的X-Real-IP，用于限流及日志 |
| ARCHIVE_BACKUP_DIR | 未设置 | 备份工具目标目录，必须显式设置或传入--out |
| ARCHIVE_API_TARGET（前端） | http://127.0.0.1:3001 | 前端开发代理目标；修改后重启前端 |

## 数据与初始化

首次启动创建数据库结构并从`seed/reference.json`初始化33家公司、24个二级类别及其下级。部门和档案为空；后续重启不会重新覆盖公司、分类或档案。种子文件随本项目提供，后端运行不依赖前端源码目录。

数据库文件及其`-wal`、`-shm`文件属于运行数据，已被忽略跟踪，不能当作无用缓存删除。浏览器刷新、关闭或清理本机存储都不会删除已保存到数据库的记录。

数据库表包含公司、部门、分类、档案、档案分类关联、编号计数器、登记/修改/作废事件、迁移指纹和版本元数据。外键、唯一档号约束与服务端业务校验共同约束数据。

## 已确认的编号规则

- 资质类：`GF-ZZ-001`。
- 固定文书分类：`GF-WS-01-01-001`。
- 更深层文书分类：`GF-WS-09-01-02-001`。
- 直接流水号类别：`GF-WS-02-001`。
- 年份类别：`GF-WS-20-2026-001`，年份由录入人选择归档年份。

计数按公司、大类、完整分类路径独立分配；年份类别额外按归档年份区分。普通类别不随年份重置，流水号至少三位，超过999自然增长。用户已在本阶段明确认可完整格式与归档年份。

登记事务同时分配号码、变更档案状态和保存登记快照。重复登记同一份已登记记录返回已有档号，不再占号；失败则回滚。作废保留记录、原因及原号，原号不复用。

公司缺少编码、分类模式仍待明确时允许保存符合字段规则的草稿，但拒绝正式登记。秘密等级继续待补，未自行创建等级选项。

## 修改与并发

每份档案有独立`recordVersion`。修改和作废必须提交读到的版本；版本冲突返回409，防止旧页面覆盖新内容。已登记档案的归属公司、大类、分类和归档年份锁定，其他业务字段可以修改；作废档案只读。

基础资料使用独立`revision`，同样检查版本。已有正式档案引用的公司编码、分类路径编码及编号模式锁定；名称调整、启停保留可用。部门被引用后不能改变所属公司。

## 旧资料迁移

前端检测到第二阶段本机非演示草稿时显示迁移按钮。迁移是显式操作，保留本机原始数据，排除演示记录。基础资料有冲突则整笔回滚并提示具体冲突；确认并统一基础资料后可重试。重复迁移不会重复新增，迁移后又发生本机修改的记录会提示核对，不覆盖数据库版本。

## 验证

```powershell
npm test
```

包含38项测试，覆盖档号、附件、Excel导入导出，以及首次初始化、Cookie/CSRF、角色和公司密级范围、原文件与导出授权、任务归属、会话撤销、账号保护、日志、并发请求隔离和北京时间提醒边界。第六阶段新增在线备份、校验与新路径恢复、附件完整性、禁止结构降级、生产静态资源保护、可信代理地址及30笔并发登记检查。写入测试均使用独立数据库。

API契约见[第三阶段接口说明](../docs/phase-3/API.md)。SQLite运行时使用Node内置模块，参考[Node.js 24 SQLite文档](https://nodejs.org/docs/latest-v24.x/api/sqlite.html)。

## 第四阶段附件与Excel

附件支持PDF、PNG、JPG/JPEG、WebP，单个20MB，元数据和文件内容保存在SQLite attachments表，同一档案相同SHA-256内容去重。作废档案只读。图片与PDF可以预览，下载保留原文件及中文名，扫描件份数不因文件上传改变。

Excel由SheetJS 0.20.3处理，依赖固定到官方发布包。支持.xls/.xlsx输入和.xlsx输出，单文件10MB、最多1000行；预览后确认只新增草稿。结果报告逐行记录失败/重复原因；导出按查询条件覆盖全部分页，最多20000条。

结构版本已升级到2，新增attachments、excel_import_jobs和索引，不重置旧记录。数据库和WAL包含附件内容，不能当作临时缓存删除。预览任务30分钟内可确认，确认幂等且事务回滚；公司等基础资料变动后要求重新预览。

第五阶段进一步升级到结构版本3，增加用户、会话、登录失败限制、秘密等级和操作日志表，并给导入任务绑定创建者。已有档案、附件与计数器保持保留；历史事件迁入日志并标注历史来源。秘密等级不预设，由管理员补充。权限、初始化、会话撤销和提醒统计口径见[第五阶段完成清单](../docs/phase-5/README.md)及[第五阶段API](../docs/phase-5/API.md)。

接口与限制见[第四阶段API](../docs/phase-4/API.md)，操作见[第四阶段完成清单](../docs/phase-4/README.md)。

## 第六阶段生产运行与维护

Linux运行包使用systemd启动本服务，通过 ARCHIVE_STATIC_DIR 托管前端生产文件，Nginx提供内网HTTPS。监听地址保持127.0.0.1，只运行一个应用实例；部署说明见[Linux配置](../deploy/linux/README.md)。健康检查返回版本1.0.0、结构版本3。

维护命令为 node scripts/maintenance.mjs：backup --db FILE --out DIR、verify --backup DIR、restore --backup DIR --target NEW_FILE、check --db FILE。备份包含附件和所有业务表，使用SQLite在线快照；恢复必须指定新文件，拒绝覆盖现有数据库及其侧文件，并清除所有会话。详见[运维与恢复](../docs/phase-6/运维与恢复.md)。

## 使用附件

1. 新增档案并保存草稿，或打开已有档案的“详情/编辑”。
2. 在“扫描附件”区域选择一个或多个文件。
3. 上传后点击“预览”查看图片或PDF，点击“下载”取得原文件。
4. 扫描件数量仍按“份”独立登记。例如扫描件3份可以只有一个多页PDF，也可以对应多个文件。

单文件最大20MB。系统检查文件实际类型与扩展名；不支持的格式或损坏的文件需要先处理为可用图片/PDF。文件不提供删除功能，避免在此阶段引入未定义的附件销毁流程。

## 使用Excel导入

1. 点击台账页“导入Excel”，下载导入模板。
2. 在“档案导入”页填写业务数据。公司编码或全称、大类、完整分类路径可以参考附带目录。
3. 编号类文本应保留前导零；日期使用YYYY-MM-DD；数量留空表示待核实，0表示没有。
4. 上传文件；旧台账缺少公司和分类时，可展开默认值区域补充。默认归档年份只用于年份类别。
5. 点击“预览校验”，查看每行结果和原因。预览不占档号、不写入档案。
6. 点击“确认导入可用N行”，仅将校验可用的行新增为草稿。错误行、重复行分别统计。
7. 下载结果报告，修正失败行后重新上传。原文件不会被修改。
8. 草稿需正式登记时，再走第三阶段已有的入账流程。

完全相同的业务内容视为重复。证书编号相同但其他业务内容不同的记录不会仅凭编号直接判重，会提供版本核查提醒。现有档号、档案ID不允许通过新增导入覆盖；需要修改现有记录时，应在系统内编辑。

3家公司编码和秘密等级继续按既定决定待补：可按公司全称匹配缺编码公司并准备草稿，正式登记仍需补编码。未配置的秘密等级不会被自动创建。部门必须先属于已有公司目录，系统不擅自创建部门。

原始《档案台账AI系统.xls》只有表头、编码规则和说明，本阶段已验证它会被识别为没有实际可导入记录，不会把说明、公司目录或编码表当作台账数据。

## 使用导出

台账页设置公司、类别、分类、部门、期限类型、登记状态、关键词等查询条件后，点击“导出台账”。导出包含全部匹配分页，而非只有当前页。文件包含原17列业务字段，以及公司、大类、分类路径、归档年份、期限模式、正式档号、登记状态、档案ID和附件文件数。

附件二进制不嵌入Excel，原文件通过档案详情下载。当前不支持通过Excel导出文件批量修改已有档案。

## 容量和任务规则

| 项目 | 限制/行为 |
| --- | --- |
| 附件 | 单个20MB；PDF、PNG、JPG/JPEG、WebP |
| Excel上传 | 单文件10MB，最多1000行数据；.xls或.xlsx |
| 导出 | 最多20000条；超过时要求缩小查询范围，不静默截断 |
| 预览任务 | 30分钟内确认；基础资料版本变化后重新预览 |
| 错误行 | 留在报告中，不能混入成功数量 |
| 写入故障 | 同次确认的新增记录整体回滚，可重试 |
| 重复确认 | 返回已有结果，不重复新增 |
| 已有业务数据 | 不通过导入覆盖或删除 |

## 启动及后续阶段

启动方式沿用前后端分离：后端`backend`目录执行npm start，前端`frontend`目录执行npm run dev。新增后端依赖后，新机器或旧环境先在backend执行npm ci。使用Node.js 24或更高版本。

本地界面：`http://127.0.0.1:5173/`；后端：`http://127.0.0.1:3001`。数据库结构已增量升级到版本2，已有第三阶段资料保留。

账号角色、公司/密级权限、完整操作日志、提醒和统计属于第五阶段。部署及备份恢复交付属于第六阶段，当前仍按本地服务运行。

# 第二阶段数据访问与第三阶段对接说明

## 当前实现

前端使用React、TypeScript及Vinext/Vite工具链，业务页面位于`frontend/features/archive/`。没有实现业务后端、数据库、账号登录或正式档号分配。

界面通过`ArchiveRepository`访问数据，当前实现是`localRepository`，将公司、部门、分类和档案草稿保存在当前浏览器的localStorage。数据键为`wansheng.archive.phase2.v1`。本机资料不代表其他设备也能读取；清理浏览器存储会删除这些本机资料。

初始数据仅包含第一阶段整理的33家公司、24个二级类别及其下级。部门和档案初始为空。只有浙江万盛股份有限公司默认启用原表文书目录，其他公司需人工确认适用范围后启用。3家缺少编码的公司、秘密等级保持待补。

演示数据由使用者显式载入，共13条，逐条标为演示数据，可单独移除，不能被误认为Excel中的实际档案。保存草稿时不分配正式档号。

## 第三阶段建议接口

以下是对接建议，尚未实现。后端可以使用独立技术栈，并与前端分别部署；本地前端开发工具链不承担正式业务数据存储。

| 建议接口 | 用途 |
| --- | --- |
| GET /api/companies | 公司列表、编码、状态、目录适用范围 |
| POST /api/companies | 新增公司 |
| PATCH /api/companies/:id | 修改公司及启停状态 |
| GET /api/departments?companyId= | 按公司查询部门 |
| POST /api/departments | 新增部门 |
| PATCH /api/departments/:id | 修改部门及状态 |
| GET /api/categories?companyId=&group= | 获取公司适用分类树及编号模式 |
| POST /api/categories | 新增分类 |
| PATCH /api/categories/:id | 修改分类及状态 |
| GET /api/archives | 按公司、大类、分类路径、关键词分页查询 |
| GET /api/archives/:id | 档案详情 |
| POST /api/archive-drafts | 保存草稿 |
| PATCH /api/archive-drafts/:id | 修改草稿 |
| POST /api/archive-drafts/:id/register | 后端校验、原子分配档号、正式登记 |

建议响应统一使用`data`及分页元信息，错误包含稳定错误码与可读提示。具体API契约在第三阶段落实，不宣称当前访问层与未来接口可以无修改替换。

## 后端必须落实的约束

- 数据权限、所有字段校验和关联关系由后端重新验证，不能依靠前端校验作为唯一约束。
- 档号由后端按已经确认的公司/大类/分类路径/年份范围分配，使用数据库唯一性和并发控制。
- 证书编号为文本，保留前导零；数量空值和0保持不同含义。
- 普通类别不按年重置；年份类别按年计数。完整拼接模板与年份来源在正式启用前明确。
- 本机草稿迁移应显式校验并报告结果，不能自动把演示数据导入正式台账。
- 账号、权限、日志、附件和导入导出按第三至第五阶段计划补齐，当前没有伪造登录或鉴权能力。

## 当前数据保护行为

本机数据通过结构校验后才进入页面；无法读取时暂停写入，保留原值。保存失败会提示未保存；多标签页修改同一份资料时检测冲突，不静默覆盖。这些机制只适用于本机草稿，不代替正式后端的并发与备份能力。

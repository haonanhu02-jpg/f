# 按钮检查与HTTP内网兼容修复

日期：2026-11-19。

## 复现与修复

生产页面通过 http://archive.test:随机端口 访问（Chromium将该主机解析到127.0.0.1，但该域名不属于浏览器安全环境）。管理员登录后点击新增档案，按钮本身启用，但页面报 crypto.randomUUID is not a function，未进入表单。与仅使用localhost检查相比，此环境复现了服务器通过普通HTTP内网地址访问时的差异。

检查全部档案业务组件后发现四个受影响入口：新增档案、新增公司、新增部门、新增分类。统一使用 createId：支持randomUUID时沿用原方法，否则使用getRandomValues生成标准UUID v4；不依赖Math.random、不改变正式档号规则。后端权限和唯一ID约束保持有效。

浏览器接口说明：[randomUUID要求安全环境](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/randomUUID)、[getRandomValues支持普通HTTP环境](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/getRandomValues)。

新增 verify-buttons.py 共7组通过，浏览器运行异常0；第三、四、五阶段页面回归分别11、8、8组通过，共34组。前端类型检查与生产构建通过。分页、年份分类、多层分类、导入部分成功、并发版本冲突等细节由原有回归脚本覆盖；测试结果不是对所有可能数据组合的承诺。

查询人员不能新增或维护档案、未授予原文件/导出权限时对应操作受限、无上一页/下一页时分页按钮禁用，均属于正常限制。测试保留并核对这些规则，不通过开放权限修复按钮。

全部写入发生在隔离测试数据库，没有使用服务器或本机正式库。报告与截图保存在frontend/outputs/下，不提交测试账号或运行数据。
